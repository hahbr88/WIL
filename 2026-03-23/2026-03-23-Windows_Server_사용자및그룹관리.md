# 2026-03-23-Windows_Server_사용자및그룹관리

## 사용자 계정

- 로컬 사용자 계정
  - AD와 관계없이 해당 서버에서만 사용하는 계정이다.
  - Windows Server 2022에서는 `Administrator`, `DefaultAccount`, `Guest`, `WDAGUtilityAccount` 같은 기본 로컬 계정을 볼 수 있다.
  - 일반적으로 실제 관리 작업은 별도의 관리자 계정을 만들어 사용하는 것이 좋다.
- 도메인 사용자 계정
  - AD 도메인에 로그인하고, 도메인 자원에 접근할 수 있는 계정이다.
  - 로그온 이름 예시 : `HANBIT\ThisUser`
  - UPN(User Principal Name) 예시 : `thisUser@hanbit.com`
  - Distinguished Name 예시 : `CN=thisUser, OU=Sales, DC=hanbit, DC=com`
  - 관리 위치 : `서버 관리자` -> `도구` -> `Active Directory 사용자 및 컴퓨터`

## 조직 구성 단위(OU)

- OU는 사용자, 그룹, 컴퓨터 등을 정리해 두는 AD 컨테이너이다.
- 쉽게 말하면 부서별 폴더 같은 개념이다.
- OU를 나누면 관리 위임과 그룹 정책 적용이 쉬워진다.
- 생성 위치 : `서버 관리자` -> `도구` -> `Active Directory 사용자 및 컴퓨터` -> 도메인 우클릭 -> `새로 만들기` -> `조직 구성 단위`

## AD 그룹

- 그룹은 사용자나 컴퓨터를 묶어서 한 번에 관리하기 위한 객체이다.
- 가장 큰 목적은 권한을 쉽게 부여하고 관리하는 것이다.
- 그룹 범위(Scope)는 다음 3가지가 있다.
  - 글로벌 그룹(Global Group)
  - 도메인 로컬 그룹(Domain Local Group)
  - 유니버설 그룹(Universal Group)

### 그룹별 설명

- 글로벌 그룹
  - 같은 도메인의 사용자나 컴퓨터를 역할별로 묶을 때 사용한다.
  - 보통 부서, 직무, 역할처럼 비슷한 사용자들을 묶는 용도로 사용한다.
  - 예: `영업팀`, `인사팀`, `개발팀`
  - 다른 도메인이나 리소스에 권한을 줄 때 직접 사용하기보다 도메인 로컬 그룹에 포함시켜 사용하는 경우가 많다.
- 도메인 로컬 그룹
  - 특정 도메인에 있는 리소스에 권한을 줄 때 사용한다.
  - 구성원으로 같은 도메인뿐 아니라 신뢰된 다른 도메인의 계정이나 그룹도 포함할 수 있다.
  - 예: `공유폴더_RW`, `프린터_사용권한`
  - 파일 서버의 공유 폴더, 프린터, 특정 서버의 권한 할당에 자주 사용된다.
- 유니버설 그룹
  - 여러 도메인에 걸친 사용자나 그룹을 하나로 묶을 때 사용한다.
  - 포리스트 전체에서 공통으로 쓰는 그룹에 적합하다.
  - 멤버십 정보가 글로벌 카탈로그에 복제되므로, 변경이 잦은 그룹에는 신중히 사용하는 것이 좋다.

### 그룹 차이점

| 구분 | 글로벌 그룹 | 도메인 로컬 그룹 | 유니버설 그룹 |
| --- | --- | --- | --- |
| 주 용도 | 계정들을 역할별로 묶음 | 리소스 권한 부여 | 여러 도메인 그룹 통합 |
| 주로 넣는 대상 | 같은 도메인의 사용자/컴퓨터 | 여러 도메인의 계정, 그룹 | 여러 도메인의 글로벌 그룹/사용자 |
| 권한을 주는 위치 | 보통 직접 권한 부여보다 상위 그룹에 포함 | 자신의 도메인 리소스에 권한 부여 | 여러 도메인 환경에서 공통 관리 |
| 이해 방식 | 사람 묶음 | 권한 묶음 | 여러 도메인 묶음 |

- 생성 위치 : `서버 관리자` -> `도구` -> `Active Directory 사용자 및 컴퓨터` -> 도메인 우클릭 -> `새로 만들기` -> `그룹`

## AGDLP

- AGDLP는 `Accounts` -> `Global Groups` -> `Domain Local Groups` -> `Permissions` 순서로 권한을 부여하는 방식이다.
- 의미는 다음과 같다.
  - `Accounts` : 사용자 계정
  - `Global Groups` : 부서나 역할별 그룹
  - `Domain Local Groups` : 리소스 권한용 그룹
  - `Permissions` : 실제 폴더, 프린터, 공유 권한
- 쉽게 정리하면
  - 사용자를 글로벌 그룹에 넣고
  - 글로벌 그룹을 도메인 로컬 그룹에 넣은 뒤
  - 도메인 로컬 그룹에 리소스 권한을 준다.
- 예시
  - 사용자 `Kim`을 `GG_Sales`에 추가
  - `GG_Sales`를 `DL_Share_RW`에 추가
  - `DL_Share_RW`에 공유 폴더 읽기/쓰기 권한 부여
- 장점
  - 사용자가 바뀌어도 그룹 구성만 바꾸면 된다.
  - 권한 관리가 단순해지고 실수가 줄어든다.
