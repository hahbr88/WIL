# 2026-03-20-Windows_Server_AD_DC

## AD DC(Active Directory Domain Controller)

AD는 사용자, 컴퓨터, 그룹 같은 자원을 중앙에서 관리하는 디렉터리 서비스이고, DC는 그 AD 데이터를 저장하고 인증과 정책 처리를 담당하는 서버이다.

핵심 역할은 다음과 같다.

- 사용자와 컴퓨터 계정을 중앙에서 관리한다.
- 도메인 로그인 인증을 처리한다.
- 그룹 정책(GPO)을 배포한다.
- 다른 DC와 AD 데이터를 복제한다.

---

## 왜 사용하는가

AD DC를 사용하면 조직 내 계정과 정책을 각 PC마다 따로 관리하지 않아도 된다.

- 계정을 한 번만 생성하면 여러 도메인 PC에서 사용할 수 있다.
- 비밀번호 정책과 보안 정책을 중앙에서 통제할 수 있다.
- 부서별 권한 관리와 계정 회수가 쉬워진다.

즉, 관리 효율성과 일관성, 보안을 위해 사용한다.

---

## 핵심 구조

### 포리스트(Forest)

포리스트는 AD의 최상위 경계이다.  
같은 포리스트 안의 도메인들은 스키마와 구성 정보를 공유한다.

- 포리스트는 AD 설계에서 가장 큰 격리 단위이다.
- 같은 포리스트 안에서는 기본적으로 전이적 Trust가 형성된다.
- 스키마와 구성 파티션은 포리스트 전체가 공유한다.
- 글로벌 카탈로그(GC)는 포리스트 전체 검색을 돕는다.

보안상 강한 분리가 필요하면 트리가 아니라 포리스트를 분리하는 편이 맞다.

### 트리(Tree)

트리는 연속된 DNS 네임스페이스를 공유하는 도메인들의 묶음이다.

- `hanbit.com`
- `second.hanbit.com`

위 두 도메인은 같은 트리에 속한다.  
반면 `partner.com`은 다른 네임스페이스이므로 별도 트리이다.

### 도메인(Domain)

도메인은 AD의 기본 운영 단위이다.

- 사용자와 컴퓨터 계정이 실제로 존재한다.
- 도메인 데이터는 같은 도메인 DC끼리 복제되고, 스키마/구성 정보는 포리스트 전체에 공유된다.
- 인증과 GPO 적용이 도메인을 기준으로 이루어진다.

### OU(Organizational Unit)

OU는 도메인 안에서 오브젝트를 논리적으로 나누는 단위이다.

- GPO를 세부적으로 적용할 수 있다.
- 관리 권한을 부분 위임할 수 있다.

OU는 권한 부여용이 아니고, 주로 정책 적용과 관리 위임용이다.

### 그룹(Group)

그룹은 권한 부여용이다.

- 파일, 폴더, 프린터 접근 권한을 그룹에 부여한다.
- 사용자는 그룹 멤버로 넣어 관리한다.

정리하면 OU는 정책과 관리용이고, 그룹은 접근 권한용이다.

---

## 오브젝트(Object)

AD의 대표 오브젝트는 다음과 같다.

- User: 사용자 계정
- Computer: 도메인에 가입한 PC나 서버 계정
- Group: 권한 부여용 묶음
- OU: 관리 단위

모든 오브젝트는 속성(Attribute)을 가지며, 이 구조는 스키마가 정의한다.

---

## DC(Domain Controller)와 운영 포인트

DC는 도메인의 인증과 디렉터리 서비스를 담당하는 핵심 서버이다.

- Kerberos와 NTLM 인증을 처리한다.
- AD 데이터베이스를 저장한다.
- DNS와 함께 운영되는 경우가 많다.
- 다른 DC와 복제한다.

실무에서는 보통 DC를 2대 이상 둔다.  
DC 한 대에 장애가 나도 인증과 디렉터리 서비스를 계속 제공하기 위해서이다.

단, DC가 일시적으로 모두 불가해도 이미 로그인한 사용자는 계속 작업할 수 있고, 도메인 가입 PC는 캐시된 자격 증명으로 로그인할 수 있는 경우가 있다.

---

## FSMO(Flexible Single Master Operations)

AD는 멀티 마스터 구조이지만, 일부 작업은 단일 역할 서버가 담당한다. 이를 FSMO라고 한다.

- Schema Master: 스키마 변경 담당
- Domain Naming Master: 도메인 추가/삭제 담당
- RID Master: SID용 RID 풀 배정 담당
- PDC Emulator: 시간 동기화, 비밀번호 변경 우선 처리, 레거시 호환 담당
- Infrastructure Master: 도메인 간 참조 갱신 담당

포리스트 단위 역할은 2개이고, 도메인 단위 역할은 3개이다.

## Kerberos 핵심

Kerberos는 AD의 기본 인증 프로토콜이다.  
사용자는 비밀번호 자체를 네트워크에 직접 보내지 않고 티켓 기반으로 인증한다.

흐름은 다음과 같다.

1. 사용자가 KDC인 DC에 인증한다.
2. TGT를 발급받는다.
3. TGT로 특정 서비스의 서비스 티켓을 요청한다.
4. 서비스 서버에 티켓을 제출해 접근한다.

중요 요소는 다음과 같다.

- KDC 역할은 DC가 수행한다.
- `krbtgt` 계정은 TGT 서명과 검증에 중요하다.
- 시간 동기화가 틀어지면 Kerberos 인증이 실패할 수 있다.

## LDAP(Lightweight Directory Access Protocol) 핵심

LDAP은 디렉터리 데이터를 조회하고 수정하는 프로토콜이다.  
AD는 LDAP으로 조회할 수 있다.

주요 포트는 다음과 같다.

- 389: LDAP
- 636: LDAPS
- 3268: GC LDAP
- 3269: GC LDAPS

LDAP에서 자주 보는 개념은 다음과 같다.

- DN: 오브젝트의 전체 경로
- RDN: 현재 컨테이너 안에서의 상대 이름
- Bind: 연결과 인증
- Search: 검색
- Add / Modify / Delete: 생성, 수정, 삭제

예시 DN은 다음과 같다.

```text
CN=kim,OU=개발팀,DC=hanbit,DC=com
```

## 보안 별도 정리

AD 보안에서 중요한 지점은 다음과 같다.

- DC는 Tier 0 자산으로 취급한다.
- Domain Admins 같은 고권한 그룹 멤버를 최소화한다.
- 오래된 사용자 계정과 컴퓨터 계정을 주기적으로 정리한다.
- 서비스 계정은 가능하면 gMSA로 대체한다.
- LDAP 서명, LDAPS, 감사 로그를 적절히 구성한다.

`Anonymous Bind` 허용, 과도한 권한 위임, 오래된 서비스 계정은 대표적인 위험 요소이다.

Kerberos 관련 대표 공격은 다음과 같다.

- Golden Ticket: `krbtgt` 해시 탈취 후 TGT 위조
- Silver Ticket: 서비스 계정 해시 탈취 후 서비스 티켓 위조
- Kerberoasting: SPN이 있는 서비스 계정 티켓을 받아 오프라인 크래킹
- AS-REP Roasting: 사전 인증이 꺼진 계정 대상 크래킹

Golden Ticket은 치명적이지만 `krbtgt` 비밀번호를 적절히 교체하면 무효화할 수 있다.

---

## 한 줄 정리

- 포리스트: 가장 큰 경계
- 트리: 연속된 DNS 네임스페이스 묶음
- 도메인: 계정, 인증, 정책이 실제로 동작하는 단위
- OU: 정책 적용과 관리 위임 단위
- 그룹: 접근 권한 부여 단위
- DC: AD와 인증을 실제로 처리하는 서버
