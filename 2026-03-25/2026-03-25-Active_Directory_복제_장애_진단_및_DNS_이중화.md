# 2026-03-25-Active_Directory_복제_장애_진단_및_DNS_이중화

## 1. 분산 시스템의 동기화 (Synchronization)

- **개념**: 여러 대의 도메인 컨트롤러(DC)가 네트워크로 연결되어 하나의 거대한 데이터베이스처럼 동작하도록 데이터를 맞추는 과정이다.
- **핵심 원칙**: 한 곳에서 변경된 정보(사용자 추가, 암호 변경 등)는 복제(Replication)를 통해 모든 DC에 전파되어 일관성을 유지해야 한다.
- **점검 도구**:
  - `repadmin /showrepl`: 개별 파트너 서버와의 복제 성공 여부 확인.
  - `repadmin /syncall`: 연결된 모든 서버에 즉시 동기화 강제 수행.

## 2. AD 핵심 권한: FSMO (5대 마스터)

AD의 안정적인 운영을 위해 특정 서버(마스터)가 전담하는 5가지 핵심 역할이다.

| 분류 | 권한 명칭 | 주요 역할 |
| :--- | :--- | :--- |
| **포레스트** | 스키마 마스터 | AD 데이터베이스의 구조(설계도) 관리. |
| | 도메인 명명 마스터 | 도메인 추가/삭제 등 이름 중복 검사 및 승인. |
| **도메인** | **PDC 에뮬레이터** | 시간 동기화, 암호 변경 주도, 그룹 정책 업데이트. (가장 중요) |
| | RID 마스터 | 신규 계정 생성 시 필요한 고유 번호표(RID) 발행. |
| | 인프라 마스터 | 다른 도메인 객체와의 참조 및 주소록 최신화. |

- **권한 확인**: `netdom query fsmo` 명령어로 현재 마스터 서버를 식별한다.

## 3. 장애 진단 및 복구 (Troubleshooting)

서버 장애 시 발생하는 현상을 진단 도구로 파악하고 대응하는 단계이다.

### 주요 진단 도구 (`dcdiag`)

- `Connectivity`: 네트워크 연결 및 서버 응답 확인.
- `Advertising`: 서버가 DC 역할을 수행 중인지 대외적으로 알리는지 확인.
- `DFSREvent`: 그룹 정책 파일(`SYSVOL`)의 복제 정상 여부 체크.

### 주요 오류 코드 및 의미

- **1722 (RPC 서버 불가)**: 대상 서버가 꺼져 있거나 서비스가 중단되어 통신할 수 없는 상태.
- **0x0000410B (RID Pool 실패)**: RID 마스터와 통신이 안 되어 새로운 계정(사용자/컴퓨터) 생성이 불가능한 상태.

## 4. DNS 가용성 및 이중화

DNS는 AD 서버를 찾는 핵심 이정표이므로 고가용성 설계가 필수적이다.

- **DNS 캐시의 함정**: 메인 서버가 죽어도 클라이언트의 캐시에 저장된 주소 덕분에 `ping`은 일시적으로 성공할 수 있어 장애 판단을 흐리게 한다.
- **`nslookup`의 중요성**: 캐시를 무시하고 서버에 직접 질의하므로, 서버 장애 시 즉시 `UnKnown` 또는 `Timeout` 에러를 출력하여 실시간 상태를 보여준다.
- **이중화 구성**: 클라이언트 설정에 **보조 DNS**를 살아있는 다른 DC IP로 지정해야 장애 시 서비스가 유지된다.

## 5. PowerShell을 이용한 강제 복구 (Seize)

마스터 서버가 영구 불능일 때, 살아있는 서버에서 권한을 강제로 뺏어오는 작업이다.

- **명령어**: `Move-ADDirectoryServerOperationMasterRole -Identity "대상서버" -OperationMasterRole 0,1,2,3,4 -Force`
- **핵심 옵션 (`-Force`)**: 정상적인 이전(Transfer)이 불가능할 때 강제 점유(Seize)를 수행하도록 명령한다.
- **오류 분석**: `ResourceUnavailable` 발생 시 대상 서버의 `ADWS`(Active Directory Web Services) 서비스가 실행 중인지 확인해야 한다.
