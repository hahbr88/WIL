# 2026-02-19-3_way_handshake

## 🔵 1️⃣ 3-Way Handshake (연결 설정 과정)

> 목적: **“우리 통신해도 될까?” 서로 확인하는 과정**

---

## 📌 기본 흐름

```bash
Client                      Server
  | ---------- SYN ----------> |
  | <------ SYN + ACK -------- |
  | ---------- ACK ----------> |
```

---

## 🔍 단계별 자세한 설명

### ① SYN (Client → Server)

* 클라이언트가 접속 요청
* SYN = Synchronize
* 자신의 초기 시퀀스 번호(ISN) 전송

예:

```bash
SYN
Seq = 1000
```

👉 "나랑 통신할래? 내 시작 번호는 1000이야"

---

### ② SYN + ACK (Server → Client)

* 서버가 수락
* 자신의 ISN 보냄
* 클라이언트 번호 +1 해서 ACK

예:

```bash
SYN
Seq = 5000
ACK = 1001
```

👉 "좋아. 나는 5000번부터 시작할게. 네 1000 잘 받았어"

---

### ③ ACK (Client → Server)

* 서버 번호 +1 해서 응답

```bash
ACK = 5001
```

👉 "너도 잘 받았어"

이제 **연결 성립 (ESTABLISHED 상태)**

---

### 🎯 왜 3번이나 필요할까?

1️⃣ 내 말이 상대에게 갔는지 확인
2️⃣ 상대 말이 나에게 왔는지 확인
3️⃣ 서로가 서로의 준비 상태 확인

👉 양방향 통신이라서 3단계가 필요함

---

### 🔵 2️⃣ 데이터 통신 중 일어나는 일

* 시퀀스 번호 증가
* ACK 번호 증가
* 윈도우 크기로 흐름 제어
* 재전송 발생 가능

TCP는 계속 **“잘 받았어”** 확인하면서 감.
