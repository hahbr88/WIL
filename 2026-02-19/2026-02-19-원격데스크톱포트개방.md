# 2026-02-19-원격데스크톱포트개방

사용자와 권한 설정을 마쳤다면, 이제 네트워크 측면에서 **'원격 데스크톱 통로(Port 3389)'**를 열어줄 차례입니다. 윈도우 서버는 기본적으로 보안을 위해 외부 연결을 엄격히 통제하기 때문입니다.

가장 빠른 **PowerShell** 방법과 눈으로 확인하며 설정하는 **GUI** 방법을 안내해 드립니다.

---

## 1. PowerShell로 즉시 개방하기 (가장 빠름)

복잡한 메뉴 클릭 없이 명령어 한 줄로 방화벽 규칙을 활성화할 수 있습니다.

1. **시작** 버튼 우클릭 -> **Windows PowerShell (관리자)** 실행
2. 아래 명령어를 복사해서 붙여넣으세요.

```powershell
# 원격 데스크톱(TCP-In) 규칙 활성화
Enable-NetFirewallRule -DisplayGroup "Remote Desktop"

```

*만약 규칙이 없다면 새로 만듭니다:*

```powershell
New-NetFirewallRule -DisplayName "Allow RDP" -Direction Inbound -LocalPort 3389 -Protocol TCP -Action Allow

```

---

## 2. 고급 보안이 설정된 Windows 방화벽(GUI) 이용

설정 상태를 직접 눈으로 확인하고 싶을 때 유용합니다.

1. **시작** 검색창에 `wf.msc`를 입력하여 **고급 보안이 설정된 Windows Defender 방화벽**을 엽니다.
2. 왼쪽 메뉴에서 **인바운드 규칙(Inbound Rules)**을 클릭합니다.
3. 목록에서 **원격 데스크톱 - 사용자 모드(TCP-In)**를 찾습니다.

* 이 항목이 회색(비활성)이라면, 마우스 우클릭 후 **규칙 사용(Enable Rule)**을 누릅니다.

1. 만약 항목이 전혀 없다면:

* 우측의 **새 규칙(New Rule)** -> **포트(Port)** -> **TCP/특정 로컬 포트(3389)** 입력 -> **연결 허용** -> 모든 프로필 체크 -> 이름(예: RDP Open) 입력 후 마칩니다.

---

## 3. 포트가 실제로 열렸는지 확인하는 방법

설정을 마친 후, 가상 머신 내부에서 포트가 제대로 대기 중인지 확인해 보세요.

1. **명령 프롬프트(CMD)**를 엽니다.
2. `netstat -an | findstr 3389`를 입력합니다.
3. 결과에 **`LISTENING`**이라는 단어가 보인다면 통로가 정상적으로 열린 것입니다.

---

## ⚠️ 보안 주의사항

앞서 이미지에서 **보안 권한(ACL)의 중요성**을 살펴본 것처럼, 방화벽 설정 역시 서버 보안의 핵심입니다.

* **공용 네트워크 주의:** 가급적 '도메인'이나 '개인' 네트워크 프로필에서만 허용하는 것이 안전합니다.
* **포트 변경:** 보안을 강화하려면 기본 포트인 **3389** 대신 다른 번호로 변경하는 것을 권장합니다. (보안 설정이 허술하면 외부 공격의 타겟이 되기 쉽습니다.)
