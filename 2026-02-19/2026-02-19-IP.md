# 2026-02-19-IP

## ✅ IP란?

**IP**
→ 인터넷에서 **데이터를 목적지까지 보내는 주소 기반 프로토콜**

📍 계층: Internet 계층
📍 역할: **패킷 전달 (Routing)**
📍 특징: 비연결형, 신뢰성 없음

---

## 🎯 한 줄 정의

> “이 데이터 어디로 가야 해?”를 담당하는 프로토콜

---

## 📦 IP가 하는 일

### 1️⃣ 주소 지정 (Addressing)

IP 주소를 사용해서

```bash
출발지 IP → 목적지 IP
```

누가 누구에게 보내는지 명확히 표시.

예:

```bash
192.168.0.10 → 8.8.8.8
```

---

### 2️⃣ 패킷 전달 (Routing)

라우터들이 IP 주소를 보고

👉 다음 목적지로 넘겨줌
👉 또 넘겨줌
👉 최종 목적지 도착

이 과정이 인터넷 전체에서 반복됨.

---

### 3️⃣ 단편화 (Fragmentation)

패킷이 너무 크면
→ 잘라서 보냄

(요즘은 주로 상위 계층에서 처리)

---

## ⚠ IP의 중요한 특징

IP는 굉장히 “단순한” 프로토콜이다.

✔ 연결 안 맺음
✔ 도착 보장 안 함
✔ 순서 보장 안 함
✔ 재전송 안 함

그냥:

> “주소 보고 보내기만 함”

---

## 🔵 그럼 신뢰성은 누가 책임지나?

👉 그게 바로 [**TCP**](./2026-02-19-TCP.md)

구조는 이렇게 돼:

```bash
Application
   ↓
TCP   ← 신뢰성 담당
   ↓
IP    ← 목적지 전달 담당
   ↓
Network
```

---

## 📦 실제 패킷 구조

```bash
[ Ethernet ]
   ↓
[ IP Header ]
   ↓
[ TCP Header ]
   ↓
[ Data ]
```

👉 IP가 큰 봉투
👉 TCP가 안쪽 안전 포장

---

## 💡 비유로 이해하기

IP = 택배 주소 시스템 📍
TCP = 안전 배송 서비스 📦

IP는 “어디로 갈지”만 책임지고
TCP는 “안전하게 도착했는지”까지 책임짐.

---

## 🔥 왜 IP는 일부러 신뢰성을 안 넣었을까?

인터넷은 전 세계를 연결하는 구조라서

* 단순해야 함
* 빠르게 처리해야 함
* 유연해야 함

그래서:

> “최소한의 기능만 넣자”
> → 나머지는 상위 계층(TCP)에 맡김

이게 인터넷 설계 철학이야.

---

## 🎯 한 줄 정리

✔ IP = 주소 기반 전달 담당
✔ 신뢰성 없음
✔ TCP가 IP 위에서 신뢰성 보완
✔ TCP/IP는 역할 분리 구조
