# 2026-03-24-Windows_Server_파일서버

## 파일 서버(File Server)

- 파일 서버는 네트워크를 통해 파일과 폴더를 중앙에서 저장, 공유, 관리하는 서버이다.
- 여러 사용자가 공용 자료를 함께 사용하고, 접근 권한을 통제하며, 백업과 저장 공간 관리를 일관되게 수행할 때 사용한다.
- Windows Server에서는 공유 폴더, NTFS 권한, 쿼터, DFS, FSRM 같은 기능을 함께 사용해 파일 서버를 구성한다.
- 주요 목적은 다음과 같다.
  - 중앙 집중형 파일 저장
  - 사용자별/부서별 접근 제어
  - 저장 공간 제한과 사용량 관리
  - 분산된 공유 폴더 통합
- 관리 위치 : `서버 관리자` -> `도구` -> `컴퓨터 관리`, `서버 관리자` -> `파일 및 저장소 서비스`

## NTFS 파일 시스템

- NTFS는 Windows 계열에서 사용하는 기본 파일 시스템으로, 보안과 안정성 기능이 강화된 파일 시스템이다.
- FAT32보다 큰 파일과 볼륨을 지원하고, 권한 설정, 압축, 암호화, 감사, 디스크 할당량 같은 고급 기능을 제공한다.
- 파일 서버에서는 보통 데이터 볼륨을 NTFS로 구성해 세밀한 접근 제어를 수행한다.
- 주요 특징
  - 파일 및 폴더 단위 권한 설정 가능
  - 압축 및 암호화(EFS) 지원
  - 감사(Auditing) 지원
  - 디스크 쿼터 설정 가능
  - 장애 복구를 위한 저널링 기능 제공

## NTFS 퍼미션

- NTFS 퍼미션은 파일이나 폴더에 대해 사용자가 어떤 작업을 할 수 있는지 지정하는 권한 체계이다.
- 공유 권한보다 더 세밀하게 설정할 수 있으며, 로컬 접근과 네트워크 접근 모두에 영향을 준다.
- 일반적으로 파일 서버에서는 `공유 권한`과 `NTFS 권한`을 함께 고려해야 하며, 실제 적용은 더 제한적인 권한 쪽으로 결정된다.

### 기본 권한 종류

- `Full Control`
  - 읽기, 쓰기, 수정, 삭제, 권한 변경, 소유권 변경까지 모두 가능하다.
- `Modify`
  - 읽기, 쓰기, 수정, 삭제는 가능하지만 권한 변경과 소유권 변경은 불가능하다.
- `Read & Execute`
  - 파일 읽기와 실행이 가능하다.
- `List Folder Contents`
  - 폴더 목록 조회가 가능하다.
- `Read`
  - 파일과 폴더 내용을 읽을 수 있다.
- `Write`
  - 새 파일 생성, 기존 파일 쓰기가 가능하다.

### NTFS 퍼미션 특징

- 권한은 기본적으로 상위 폴더에서 하위 폴더와 파일로 상속된다.
- 필요하면 상속을 끊고 하위 폴더에 별도 권한을 줄 수 있다.
- `Deny` 권한은 `Allow`보다 우선 적용되므로 신중하게 사용해야 한다.
- 실무에서는 사용자에게 직접 권한을 주기보다 그룹에 권한을 주는 방식이 관리에 유리하다.
- 파일 서버에서는 보통 다음 원칙을 많이 사용한다.
  - 공유 권한은 넓게 설정
  - 실제 제어는 NTFS 권한으로 수행

### 권한 설정 위치

- 폴더 우클릭 -> `속성` -> `보안`
- 고급 설정 : 폴더 우클릭 -> `속성` -> `보안` -> `고급`

## NTFS 쿼터

- NTFS 쿼터는 사용자별 디스크 사용량을 제한하는 기능이다.
- 하나의 NTFS 볼륨 안에서 각 사용자가 사용할 수 있는 저장 공간의 최대치를 설정할 수 있다.
- 저장 공간이 부족해지는 상황을 예방하고, 특정 사용자가 과도하게 용량을 점유하는 것을 막을 때 유용하다.

### 쿼터 기능

- 사용자별 사용량 추적
- 경고 임계값 설정
- 저장 한도 초과 시 기록 또는 저장 차단
- 볼륨 단위 적용

### 구성 방법

- 드라이브 우클릭 -> `속성` -> `할당량`
- `할당량 관리 사용`을 체크한다.
- 필요하면 `할당량 제한 초과 사용자에게 디스크 공간 거부`를 설정한다.
- 기본 할당량 한도와 경고 수준을 지정한다.
- `할당량 항목`에서 특정 사용자에게 별도 쿼터를 줄 수 있다.

## 분산파일시스템(Distributed File System, DFS)

- DFS는 여러 파일 공유를 하나의 논리적 이름공간으로 묶어 사용자에게 제공하는 기능이다.
- 사용자는 실제 서버 이름을 직접 알지 않아도 되고, 통합된 경로로 파일 공유에 접근할 수 있다.
- 예를 들어 실제 서버가 여러 대여도 사용자는 `\\contoso.com\Share` 같은 일관된 경로만 기억하면 된다.
- 서버 교체나 공유 위치 변경이 발생해도 사용자 경로를 유지하기 쉬워 관리성이 좋아진다.

### DFS 구성 요소

- DFS 네임스페이스(DFS Namespace)
  - 여러 공유 폴더를 하나의 논리 경로 아래 묶어 보여주는 기능이다.
- DFS 복제(DFS Replication)
  - 여러 서버 간 파일을 복제해 가용성과 분산 저장을 지원하는 기능이다.

## DFS 구현방법

- `서버 관리자` -> `역할 및 기능 추가`에서 `DFS 네임스페이스`, `DFS 복제` 역할 서비스를 설치한다.
- `서버 관리자` -> `도구` -> `DFS 관리`를 연다.
- 새 네임스페이스를 만든다.
  - 도메인 기반 네임스페이스
  - 독립 실행형 네임스페이스
- 네임스페이스 아래에 폴더를 만들고, 실제 공유 폴더를 폴더 대상(Folder Target)으로 추가한다.
- 고가용성이 필요하면 동일 폴더 대상에 여러 서버의 공유를 추가한다.
- 서버 간 데이터 동기화가 필요하면 복제 그룹을 만들어 DFS 복제를 구성한다.

### 도메인 기반 네임스페이스와 독립 실행형 차이

| 구분 | 도메인 기반 | 독립 실행형 |
| --- | --- | --- |
| 저장 위치 | Active Directory에 저장 | 로컬 서버에 저장 |
| 관리 편의성 | 도메인 환경에서 유리 | 단독 서버 환경에 적합 |
| 경로 예시 | `\\contoso.com\Public` | `\\Server01\Public` |
| 고가용성 | 비교적 유리 | 상대적으로 제한적 |

## FSRM 파일 서버 리소스 관리자

- FSRM(File Server Resource Manager)은 파일 서버의 저장 공간과 파일 사용 정책을 관리하는 기능이다.
- 단순한 NTFS 쿼터보다 더 세밀한 용량 정책과 파일 분류, 파일 차단, 저장 보고서를 제공한다.
- 기업 환경에서 부서별 용량 제한, 특정 확장자 차단, 저장소 사용 분석에 자주 사용된다.

### FSRM 주요 기능

- 쿼터 관리
  - 폴더 단위로 용량 제한을 설정할 수 있다.
- 파일 스크리닝(File Screening)
  - 특정 확장자의 파일 저장을 차단하거나 경고할 수 있다.
- 스토리지 리포트
  - 대용량 파일, 오래된 파일, 중복 파일 등을 분석할 수 있다.
- 파일 관리 작업(File Management Tasks)
  - 파일 이동, 만료, 분류 기반 작업 자동화가 가능하다.

## FSRM 구성방법

- `서버 관리자` -> `역할 및 기능 추가`에서 `파일 서버 리소스 관리자`를 설치한다.
- 설치 후 `서버 관리자` -> `도구` -> `파일 서버 리소스 관리자`를 연다.

### 쿼터 구성

- `할당량 관리` -> `할당량` -> `할당량 만들기`
- 대상 폴더를 지정한다.
- 템플릿 기반 또는 사용자 지정으로 용량 제한과 알림 조건을 설정한다.

### 파일 스크린 구성

- `파일 스크리닝 관리` -> `파일 스크린` -> `파일 스크린 만들기`
- 대상 폴더를 지정한다.
- 차단할 파일 그룹을 선택한다.
  - 예 : 오디오/비디오 파일, 실행 파일
- 필요하면 이메일 경고, 이벤트 로그 기록, 스크립트 실행을 설정한다.

### 스토리지 리포트 구성

- `스토리지 보고서 관리` -> `보고서 작업` -> `새 보고서 작업 예약`
- 보고서 종류와 대상 경로, 실행 주기를 설정한다.
- 생성 가능한 보고서 예시
  - 대용량 파일 보고서
  - 중복 파일 보고서
  - 파일 소유자 보고서
  - 최근 사용되지 않은 파일 보고서

## 파일 서버 구성 시 주의점

- 공유 권한과 NTFS 권한을 함께 설계해야 하며, 보통 실제 접근 통제는 NTFS 권한 중심으로 구성한다.
- 사용자 계정에 직접 권한을 부여하기보다 보안 그룹 기반으로 권한을 관리하는 편이 안전하다.
- DFS를 사용할 때는 네임스페이스와 실제 공유 구조를 분리해서 이해해야 한다.
- FSRM 쿼터는 폴더 단위, NTFS 쿼터는 볼륨 단위라는 차이를 구분해야 한다.
- 운영 전에 테스트 공유 폴더에서 권한, 쿼터, 파일 스크리닝 정책을 먼저 검증하는 것이 좋다.
