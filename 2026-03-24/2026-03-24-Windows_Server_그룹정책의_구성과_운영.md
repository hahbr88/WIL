# 2026-03-24-Windows_Server_그룹정책의_구성과_운영

## 그룹 정책(Group Policy)

- 그룹 정책은 Active Directory 환경에서 사용자와 컴퓨터의 설정을 중앙에서 관리하는 기능이다.
- 개별 PC마다 직접 설정하지 않고, 도메인/사이트/OU 단위로 일괄 적용할 수 있다.
- 보안, 바탕 화면 환경, 로그인 스크립트, 소프트웨어 배포 같은 관리 작업을 표준화할 때 사용한다.
- 적용 대상은 크게 두 가지다.
  - 컴퓨터 구성 : 부팅 시점과 컴퓨터 자체 설정에 적용
  - 사용자 구성 : 로그인한 사용자 환경과 사용자 설정에 적용
- 관리 위치 : `서버 관리자` -> `도구` -> `그룹 정책 관리`

---

## GPO(Group Policy Object)

- GPO는 실제 정책 설정이 저장되는 객체이다.
- 그룹 정책은 개념이고, GPO는 그 정책을 담고 배포하는 단위라고 이해하면 된다.
- 하나의 GPO 안에는 컴퓨터 구성과 사용자 구성 설정이 함께 들어갈 수 있다.
- GPO는 사이트(Site), 도메인(Domain), OU에 연결(Link)해서 사용한다.
- 대표 예시
  - 비밀번호 정책 강제
  - 제어판 접근 제한
  - 시작 스크립트 실행
  - 특정 폴더를 네트워크 경로로 리디렉션

---

## 그룹정책 상속

- 그룹 정책은 AD 구조를 따라 상위에서 하위로 상속된다.
- 기본 적용 순서는 `Local` -> `Site` -> `Domain` -> `OU` 이며, 보통 LSDOU 순서라고 부른다.
- 같은 설정이 여러 단계에서 충돌하면 나중에 적용되는 하위 단계 정책이 우선하는 경우가 많다.
- 즉, 상위 도메인 정책보다 하위 OU 정책이 더 구체적이면 하위 OU 설정이 최종 적용될 수 있다.
- 상속을 잘 활용하면 공통 정책은 상위에, 부서별 예외 정책은 하위 OU에 나누어 구성할 수 있다.

### 상속 시 가능한 작업

- 보안 설정
  - 암호 정책, 계정 잠금 정책, 감사 정책, 사용자 권한 할당 등을 배포할 수 있다.
- 스크립트 지정
  - 시작/종료 스크립트, 로그온/로그오프 스크립트를 지정할 수 있다.
- 폴더 리디렉션
  - 바탕 화면, 문서, AppData 같은 사용자 폴더를 파일 서버 경로로 이동시킬 수 있다.
- 소프트웨어 설정
  - MSI 기반 프로그램 배포, 게시(Publish), 할당(Assign) 같은 설정을 구성할 수 있다.

### 상속 관련 제어

- 상속 차단(Block Inheritance)
  - 하위 OU에서 상위 정책 상속을 막는 기능이다.
  - 단, 강제된 정책은 차단하더라도 계속 적용될 수 있다.
- 강제(Enforced)
  - 상위 GPO를 하위에서 무시하지 못하도록 하는 기능이다.
  - 예전 용어로 `No Override`라고도 본다.
- 연결 순서(Link Order)
  - 같은 OU에 여러 GPO가 연결된 경우 적용 우선순서를 조정할 수 있다.

## 그룹정책 적용 및 해제 방법

### 그룹정책 적용 방법

- `그룹 정책 관리` 콘솔에서 사이트, 도메인, OU를 우클릭한 뒤 `이 도메인에 GPO 만들기 및 여기 연결` 또는 기존 GPO 연결을 선택한다.
- 새 GPO를 만든 뒤 `편집`을 눌러 필요한 정책을 구성한다.
- 대상 사용자나 컴퓨터가 해당 OU 안에 있어야 정책이 정상 적용된다.
- 보안 필터링(Security Filtering)으로 특정 그룹에게만 적용 범위를 제한할 수 있다.
- 필요하면 `gpupdate /force` 명령으로 정책을 즉시 다시 적용할 수 있다.

### 그룹정책 해제 방법

- 링크 해제
  - GPO와 사이트/도메인/OU의 연결만 제거하는 방식이다.
  - GPO 객체 자체는 남아 있으므로 다른 위치에서 다시 사용할 수 있다.
- GPO 삭제
  - 정책 객체 자체를 삭제하는 방식이다.
  - 연결뿐 아니라 GPO 내용도 함께 제거되므로 신중해야 한다.
- 설정 비활성화
  - GPO 안에서 컴퓨터 구성 또는 사용자 구성 자체를 비활성화할 수 있다.
  - 또는 개별 정책 항목을 `구성 안 함`으로 되돌려 영향을 없앨 수 있다.
- 적용 제외
  - 보안 필터링이나 WMI 필터 조건을 변경해 특정 대상에만 적용되지 않도록 조정할 수 있다.

### 적용 결과 확인

- `gpresult /r`
  - 현재 사용자/컴퓨터에 적용된 GPO 목록을 확인할 수 있다.
- `rsop.msc`
  - 결과 집합 정책(Resultant Set of Policy)을 GUI로 확인할 수 있다.
- 관리 위치
  - `서버 관리자` -> `도구` -> `그룹 정책 관리`

## 그룹정책 모델링 마법사

- 그룹정책 모델링 마법사는 특정 사용자와 컴퓨터가 어떤 GPO를 적용받을지 시뮬레이션하는 기능이다.
- 실제 적용 전에 OU 이동, 보안 그룹 변경, 느린 네트워크, 루프백 처리 같은 조건을 가정해 결과를 예측할 수 있다.
- 정책 충돌이나 상속 결과를 미리 검토할 때 유용하다.
- 사용 위치 : `그룹 정책 관리` -> 포리스트/도메인 선택 -> `그룹 정책 모델링` 우클릭 -> `그룹 정책 모델링 마법사`
- 결과에서는 다음 내용을 확인할 수 있다.
  - 어떤 GPO가 적용되는지
  - 어떤 GPO가 거부되었는지
  - 보안 필터링, WMI 필터, 상속 구조에 의해 결과가 어떻게 바뀌는지

## 그룹정책 관리(백업, 복원, 복사)

- GPO는 운영 중 변경 실수가 자주 발생하므로 백업과 복원 기능이 중요하다.
- `그룹 정책 관리` 콘솔에서 GPO를 우클릭하면 관리 기능을 사용할 수 있다.

### 백업

- 특정 시점의 GPO 설정을 파일 형태로 저장하는 기능이다.
- 정책 변경 전 백업해 두면 문제가 생겼을 때 빠르게 되돌릴 수 있다.
- 사용 위치 : GPO 우클릭 -> `백업`

### 복원

- 이전에 백업한 GPO 상태로 되돌리는 기능이다.
- 잘못 수정된 정책을 이전 정상 상태로 복구할 때 사용한다.
- 사용 위치 : GPO 우클릭 -> `백업 관리` 또는 `복원`

### 복사

- 기존 GPO를 다른 이름의 새 GPO로 복제하는 기능이다.
- 비슷한 정책을 부서별로 조금씩 다르게 만들 때 편리하다.
- 같은 도메인 안뿐 아니라 다른 도메인으로 가져오기/내보내기 작업에도 활용할 수 있다.
- 사용 위치 : GPO 우클릭 -> `복사`, 붙여넣기 대상 컨테이너에서 `붙여넣기`

### 관리 시 주의점

- 운영 중인 기본 정책(Default Domain Policy, Default Domain Controllers Policy)은 직접 과도하게 수정하지 않는 편이 좋다.
- 큰 변경 전에는 반드시 백업을 먼저 수행하는 것이 안전하다.
- 테스트 OU를 만들어 새 GPO를 먼저 검증한 뒤 운영 OU에 연결하는 방식이 실무에서 안정적이다.
